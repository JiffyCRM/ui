# SSO Enterprise Login Page Plan

## Goal
Create a static, integration-free SSO enterprise login experience for the JiffyCRM Next.js app:
- Starter/home page titled `JiffyCRM` with a login entry point.
- Dedicated `/login` page using existing shadcn/base-ui components, with enterprise SSO provider buttons and an email continuation form (no real auth).

## Scope
- Add `app/login/page.tsx`.
- Replace the default Next.js starter content in `app/page.tsx` with a minimal JiffyCRM landing page containing a "Log in" button linking to `/login`.
- Update page metadata titles to `JiffyCRM`.
- No backend, API routes, database, or auth provider integration.

## Affected Files
- `app/page.tsx`
- `app/login/page.tsx`
- Optional: `app/layout.tsx` metadata title

## Components To Use
- `components/ui/card.tsx`: `Card`, `CardHeader`, `CardTitle`, `CardDescription`, `CardContent`, `CardFooter`
- `components/ui/button.tsx`: `Button`
- `components/ui/input.tsx`: `Input`
- `components/ui/label.tsx`: `Label`
- `components/ui/separator.tsx`: `Separator`
- `components/ui/badge.tsx`: `Badge`
- `lucide-react`: `Building2`, `Mail`, `KeyRound`, `ShieldCheck`, `Lock`, `ArrowRight`
- `next/link`: `Link`

## Home Page Design
- Centered container with `JiffyCRM` heading and short subtitle.
- Card with primary "Log in" button as `Link` to `/login`.
- Optional secondary text: "Enterprise single sign-on available."

## Login Page Design
- Two-column responsive layout:
  - Left brand panel (hidden on small screens): JiffyCRM branding, enterprise SSO value props, security badge.
  - Right panel: centered login card.
- Login card:
  - Title: "Sign in to JiffyCRM"
  - Description: "Choose your organization's identity provider."
  - Full-width SSO buttons:
    - Continue with Microsoft Entra ID
    - Continue with Google Workspace
    - Continue with Okta
    - Continue with SAML SSO
  - `Separator` with "or continue with email"
  - Email `Input` + "Continue" `Button`
  - Footer links: Help, Privacy, Terms
- Buttons are non-submitting/static (`type="button"`), no handlers beyond optional `preventDefault`.
- Use `"use client"` only if a form submit handler is needed; otherwise keep server component.

## Data Flow
- No data flow or state beyond local form input.
- No navigation on SSO buttons (static UI).
- Home "Log in" navigates to `/login` via `next/link`.

## Failure Modes / Edge Cases
- Empty email: rely on browser `required` validation if form is used.
- Mobile layout: stack brand panel above or hide it; keep card full width.
- Dark mode: use existing theme variables only.
- No provider icons available: use generic lucide icons or text-only buttons.

## Validation
- Run `npm run lint`.
- Run `npm run build` to verify Next.js compile and route generation.
- Manual check: `/` shows JiffyCRM and login button; `/login` renders SSO page and is responsive.

## Out Of Scope
- Real authentication, SSO/OIDC/SAML integration, session management, redirects after login, and dashboard content.
